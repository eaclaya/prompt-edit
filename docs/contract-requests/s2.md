## 2. (FYI, not blocking) unknown token types

PLAN.md §7 asks that "missing or unknown token types fail loudly". With the contract's DTOs an unknown
type can't reach `CostCalculator` (`Usage`/`Rates` have exactly the four `TokenType` fields, and the
calculator walks `TokenType::cases()`), and missing types already throw in `Usage::fromArray()` /
`Rates::fromArray()` — S2 tests both. `Usage::fromArray()` silently ignores *extra* keys (it must accept
`total_tokens`). If S1/S8 wants a new token type in an API payload to fail loudly, that is a change to
`App\Contracts\Data\Usage::fromArray()` (S1-owned), e.g. reject keys outside `TokenType` ∪ {`total_tokens`}.
S2 has not made it.
